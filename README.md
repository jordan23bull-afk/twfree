# Скрининг акций и фьючерсов MOEX

Отбор акций TQBR и фьючерсов RFUD за последнюю торговую сессию и график в одном одиночном файле.

## Файлы

| Файл | Что это |
|---|---|
| `rosn.html` | График и вочлист. Один файл: Lightweight Charts вшит внутрь. Данные берёт **только** из `data.json`, своего отбора в браузере нет. |
| `screener.mjs` | Отбор: запросы к MOEX ISS, фильтры, сборка истории, запись `data.json`. Запуск `node screener.mjs`. |
| `data.json` | Результат: вочлист с флагами, POC последнего дня + дневные OHLC по отобранным тикерам. У каждого тикера поле `board` — путь ISS его площадки. |

## Как обновить данные

```bash
node screener.mjs
git add data.json
git commit -m "Обновил данные за <дата>"
git push
```

Затем страница подхватит файл автоматически. Параметры можно задать флагами:

```bash
node screener.mjs --value 5000000 --atr 100 --days 60
```

Дополнительно можно задать, какие типы бумаг брать (по умолчанию `1,2` — только акции):

```bash
node screener.mjs --types 1,2
```

## Правила отбора

1. **Только акции.** Берутся бумаги с типом `SECTYPE` из {`1` (обыкновенные), `2` (привилегированные)}. Всё остальное отсеивается: ETF (`J`), ПИФы и ИПИФ (`A`, `B`), ЦФА (`9`), депозитарные расписки (`D`).
2. Оборот за день `VALUE` от 10 000 000 ₽ и объём `VOLUME` больше нуля.
3. ATR за день не меньше 150 пунктов: `(HIGH − LOW) / MINSTEP`, где `MINSTEP` — шаг цены конкретного тикера (у разных бумаг он разный, поэтому берётся отдельно для каждой).
4. Флаг: зелёный при `CLOSE > OPEN`, красный при обратном. При равных значениях — красный.

Сортировка — по убыванию ATR.

## Фьючерсы

Кроме акций TQBR в вочлист всегда добавляются фьючерсы `IMOEXF` (индекс МосБиржи) и `MXZ6` (фьючерс на индекс MIX, контракт MIX-12.26). Список — в `EXTRA_FUTURES` в начале `screener.mjs`.

Они лежат на другой площадке — `futures/markets/forts/boards/RFUD`, поэтому путь ISS у каждого тикера свой. Скринер кладёт его в `data.json` полем `board`, и `rosn.html` по нему собирает адрес для остальных таймфреймов.

Для фьючерсов ATR и POC считаются теми же функциями, но отсев по обороту и минимальному ATR не применяется — их шаг цены (`MINSTEP`) несопоставим с шагом акции. Отключается флагом `--no-futures`:

```bash
node screener.mjs --no-futures
```

Числа ISS для фьючерсов приходят с запятой как десятичным разделителем (`"2248,00000"`), поэтому в скрипте есть `num()`, которая приводит запятую к точке.

## POC дня

Скринер сам считает POC (Point of Control) — цену, по которой за сессию прошло больше всего объёма.

Как считается:

1. Для каждой отобранной бумаги запрашиваются **минутные свечи** последнего торгового дня.
2. Внутри минуты распределение объёма по ценам неизвестно, поэтому объём бара распределяется равномерно по его диапазону `[low, high]`.
3. Объёмы складываются в корзины с шагом цены бумаги (`MINSTEP`), POC — корзина с максимальным объёмом.
4. В `data.json` попадает три поля: `poc` (цена), `pocShare` (доля дневного объёма в корзине POC, %) и `pocGap` (отклонение закрытия от POC, %).

График рисует POC пунктирным уровнем с меткой цены, в легенде тикера — значение и отклонение.

Тики для этого не подходят: эндпоинт сделок MOEX ISS игнорирует `date`, историю тиков не отдаёт — доступна только текущая сессия. Минутные свечи историю возвращают, поэтому POC и считается из них.

Расчёт выключается флагом `--no-poc`:

```bash
node screener.mjs --no-poc
```

## Таймфреймы

`1 д` рисуется из `data.json` и работает всегда. Остальные (`1 мин`, `5 мин`, `1 ч`, `1 нед`) страница запрашивает у биржи напрямую, поэтому им нужен интернет.

## Обновление по расписанию

Пока файлы обновляются вручную. Автоматизацию можно добавить GitHub Actions с запуском по cron после закрытия торгов, чтобы скрипт сам коммитил свежий `data.json`.
